1. Identifique o erro e corrija somente o fluxo afetado. O Android usa Capacitor com assets locais; push no GitHub/site NÃO atualiza o APK instalado.

4. Inspecione package.json e scripts. Execute testes pertinentes e npx tsc -b. Use npm run android:apk; o wrapper escolhe Java 21 em .android-tools e o SDK local. 5. Execute npm run android:release-files somente após o build. Ele valida versão real do manifesto e gera APK, notas e hash em .android-tools/releases/android-vVERSAO. Não renomeie APK antigo como se fosse versão nova.

SHA256 do ARQUIVO APK muda a cada build e é diferente da impressão digital do certificado cadastrada no Firebase.
7. A release deve ter tag android-vX.Y.Z e anexo NovaesWeb-Entregador-vX.Y.Z-codeN.apk, com .sha256 correspondente; publicar como release final, não draft/prerelease. O verificador só avisa se N for maior que o build instalado. Verificar versões automaticamente fica em Extrato > Atualizações do aplicativo. O Android exige confirmação do usuário para instalação; não prometa instalação silenciosa. Não usar código remoto para contornar atualização nativa.
